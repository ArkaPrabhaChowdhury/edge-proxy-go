A proxy small enough to change during an incident

The project keeps the core routing path in Go code: parse the request, resolve policy, evaluate the limiter, select a backend, forward upstream, and record what happened.

client request request id, forwarded headers, route and method are captured at ingress.
rate policy default and route/API-key policies resolve before backend selection.
backend pool load, latency, health, drain state, and breaker state affect routing.
upstream service responses return with propagated request ids and structured logs.
Adaptive routing

Backend choice accounts for in-flight load and observed latency instead of only rotating through a list.

Abuse control

Redis stores sliding-window state, repeated abuse, throttle events, and temporary block decisions.

Runtime operations

Drain, disable, enable, inspect, and reload the parts that can safely change without restarting the proxy.

Traceable requests

Every request can carry an ID, access log record, Prometheus metrics, and optional OTLP trace context.

Backend state stays visible and controllable

Use the dashboard to inspect backend health, breaker state, load, errors, and latency, then change rotation state without shell access.
